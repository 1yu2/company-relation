# Skill: 企业尽调外部数据补数

## 目标

在企业尽调场景中，当内部 MySQL 事实主库存在缺口（缺失、过期、部分覆盖、冲突）时，
通过 `query_external_company_data` 工具查询外部公开数据作为补充证据。

## 使用前提

1. 必须已经通过 `investigate_company` 确认企业身份，并取得 `company_context.eid`。
2. 不得根据模型猜测 `eid`，也不得用外部数据源返回的企业名称覆盖已确认企业。
3. 仅当用户问题涉及以下场景时才调用本工具：
   - 融资历史（内部无记录或记录不全）
   - 财务指标（营收、利润、资产负债等）
   - 上市公司基本资料、股东、公告或重大事件
   - 内部数据与已知信息存在冲突，需要外部对照

## 调用规则

- 先调用 `investigate_company` 获取内部结果。
- 如果内部结果已经完整且置信度高，不要再调用外部工具。
- 仅在以下情况调用 `query_external_company_data`：
  - 内部结果明确提示数据缺失、过期或冲突；
  - 用户明确要求补充外部公开信息；
  - 主题属于 `profile`、`financials`、`financing`、`shareholders`、`news` 之一。
- 传入的 `confirmed_eid` 必须来自 `investigate_company` 返回的 `company_context.eid`。
- `topics` 按用户意图选择；不明确时优先使用 `["profile", "financials"]`。

## 结果表述约束

- 外部事实必须标注来源、Provider 和获取时间。
- 外部无结果时，只能表述为“在当前外部数据源和时间窗口内未查到可验证记录”，
  不能表述为“企业没有融资”“企业不存在风险”等绝对结论。
- 当内外部数据冲突时，必须并列展示双方来源和日期，不静默裁决。
- 不得把外部数据写回内部 MySQL 或修改已确认企业身份。

## 安全与隐私

- 不要向外部接口发送用户密钥、内部连接信息或未脱敏的企业隐私数据。
- 不要记录完整原始响应或敏感凭据。
