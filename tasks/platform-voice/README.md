# 平台级语音交互任务清单

本目录维护与具体业务领域无关的平台级语音能力。首版只建设非实时的语音输入和按需语音输出：语音输入先转成可编辑文字，再进入现有 AgentRun；语音输出只朗读已经生成的助手文字或用户选中的内容，不新建语音 Agent，也不复制任何领域逻辑。

## 核心决策

- 语音是所有 Agent 可复用的输入输出渠道，不是新的 Agent 类型。
- ASR 结果必须回填输入框并允许用户确认或编辑，首版不自动发送。
- TTS 不重新执行 Agent，也不再次自由生成事实；朗读内容必须来自已有助手消息或用户选中文本。
- 默认不自动播放，不默认朗读长回答全文；朗读范围由用户问题和页面操作共同决定。
- 原始录音默认临时使用并及时清理；数据库继续以文字消息作为对话事实记录。
- ASR/TTS 统一复用“模型供应商”的 URL、Key 与模型配置，不再维护独立语音凭据。
- 当前首版供应商协议为 Qwen-ASR 与 Qwen-TTS，同类型只允许一个启用模型。
- 首版不绑定企业尽调或其他专业领域，不建设专业术语词典。

## 建议实施顺序

```text
Wave 1：冻结语音契约与供应商适配边界
  ↓
Wave 2：录音、上传、ASR、转写确认
  ↓
Wave 3：助手消息与选中文本按需 TTS
  ↓
Wave 4：隐私清理、限流、测试与文档收口
```

## 公共约束

1. 复用现有 AgentRun、消息持久化、请求队列、SSE 和取消链路，不新建第二套语音会话系统。
2. 新增前端 API 统一放在 `web/src/apis`，新增后端领域逻辑优先放在 `backend/package/yuxi/voice`。
3. ASR/TTS 供应商通过明确接口适配，路由和前端不直接依赖供应商 SDK。
4. API Key、Token 和供应商连接信息统一从模型供应商读取，不写入日志、任务 payload、测试或文档。
5. 音频必须限制格式、大小和时长；失败时显式返回，不静默提交空消息或旧转写。
6. 助手文字是语音输出的唯一内容来源；页面文字、消息历史和音频之间不得出现事实分叉。
7. 所有开发、测试、格式化和 Lint 在现有 Docker Compose 容器中完成。

## 后续扩展

以下能力在首版数据证明有使用价值后再拆分任务：

- 流式 ASR 和流式 TTS；
- 用户打断、边生成边播放和实时双向语音；
- 自动生成长回答的受约束朗读摘要；
- 用户级默认声音、语速和自动播放偏好；
- 专业领域词典、术语纠错和领域语音适配器。
