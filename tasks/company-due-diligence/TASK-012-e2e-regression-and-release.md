# TASK-012：企业尽调核心链路端到端回归

| 属性 | 内容 |
| --- | --- |
| 状态 | 已完成 |
| 类型 | 串行收口任务 |
| 优先级 | P0 |
| 依赖 | `TASK-006`、`TASK-007`、`TASK-010` |

## 目标

把主聊天自然语言输入、企业身份解析、受控工具计划、Claim Ledger、动态输出和专题/完整报告串成可重复验证的端到端链路。

## 回归范围

1. 主聊天可以选择全局共享的企业尽调智能体。
2. 无企业上下文的全局白名单问题返回 `global_scope`。
3. 依赖企业但无法确认主体的问题返回 `needs_context`。
4. 问题中的企业全称、股票代码或信用代码可以自动解析。
5. 企业基本信息、股东、关系路径和文本证据查询返回来源与数据质量状态。
6. 自然语言报告意图和报告快捷入口进入同一报告工作流。
7. 报告任务可以完成、下载 JSON/Markdown，并在测试后清理任务和 MinIO 产物。
8. 数据源不可用、无数据、过期和冲突不能被混为同一状态。

## 验收标准

- [x] 主聊天能够调用 `investigate_company` 并保存成功工具调用记录。
- [x] 企业问答、关系路径和文本证据查询返回可追溯来源。
- [x] 普通用户不需要填写内部 `eid` 或选择内部查询模式。
- [x] `Claim Ledger` 不允许输出缺少有效 `source_id` 的事实。
- [x] 专题报告和完整报告能够异步生成并下载。
- [x] 企业尽调单元测试、接口测试和关键 E2E 回归通过。
- [x] 日志、测试夹具和文档不包含数据库凭据或完整连接信息。

## 非目标

- 不提供企业尽调专属质量评测、QA Benchmark、性能评测或发布门禁。
- 不执行真实数据库高并发容量测试。
- 不修改广东企业 MySQL 源表。
