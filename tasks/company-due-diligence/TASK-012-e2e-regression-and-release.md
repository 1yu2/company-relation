## 端到端场景

1. 企业名称搜索出现唯一结果并完成基本信息问答。
2. 股票代码解析后查询当前股东、持股比例、认缴和实缴。
3. 查询产品、融资、处罚、许可和知识产权列表。
4. 两家企业共同股东和最多三跳路径。
5. 低置信度同名关系正确降级或拒答。
6. 新闻或处罚问题返回文本证据和结构化来源。
7. 创建完整报告、查看章节进度、处理部分失败并下载 JSON/Markdown。
8. 运行人工 Golden 质量评测并查看错误详情。
9. 运行安全性能评测并查看 P50/P95/P99 和连接池指标。
10. MySQL、Neo4j、Milvus 或 LLM 单项不可用时返回正确状态。

## 发布门禁

正式阈值在首批人工 Golden 完成后冻结，至少包含：

- 关键字段严格准确率不得低于约定基线。
- 高置信度路径准确率不得低于约定基线。
- 输出企业事实必须全部存在来源，幻觉门禁接近 0。
- 歧义、无数据、过期和低置信度拒答必须通过。
- 报告必需章节和数据质量声明完整。
- 核心查询和报告性能不超过约定 P95。
- 连接池无泄漏、无非预期溢出。
- AkShare 公开基线回归不得因新系统接入而破坏。

## 实现步骤

1. 确认所有前置任务状态和 API 契约已经冻结。
2. 准备不含凭据和个人明细的固定测试数据。
3. 在 Docker Compose 中检查现有服务和日志，不重复拉取镜像。
4. 按简单问答、多跳、报告、质量和性能顺序执行 E2E。
5. 注入单数据源故障并验证显式失败和恢复。
6. 执行相关单元测试、集成测试、E2E、前端测试和 Lint。
7. 运行质量 Golden 和安全性能基线，保存版本化报告。
8. 更新文档中的“当前状态”，不得把未通过项写为已完成。
9. 输出发布验收报告和已知限制。

## 验收标准

- [ ] 用户可以从前端完成简单问答并查看来源。
- [ ] 用户可以从前端完成多跳查询并查看路径。
- [ ] 用户可以生成并下载完整报告。
- [ ] 用户可以从前端启动和查看质量评测。
- [ ] 用户可以从前端启动安全性能评测。
- [ ] 核心 API、任务进度和导出产物状态一致。
- [ ] 质量和性能门禁报告包含代码、数据和配置版本。
- [ ] 数据源故障不会被误报为无数据。
- [ ] 日志、测试、快照和文档没有敏感连接信息。
- [ ] 所有现有相关回归通过。

## 非目标

- 不在没有数据源负责人允许时执行真实库高并发容量测试。
- 不自动提交或推送 GitHub；提交和推送由用户明确要求后执行。
- 不把已知数据覆盖限制包装成系统全量能力。
- 不处理与企业尽调无关的既有测试失败。
