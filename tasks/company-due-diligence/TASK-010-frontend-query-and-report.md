## 目标

企业问答、关系查询、风险调查和专题/完整报告统一从主聊天窗口调用全局“企业尽调智能体”。不再维护独立企业尽调工作台，避免出现第二套调查输入输出。

## 最终入口

- 普通用户在主聊天选择 slug 为 `company-due-diligence` 的全局 Agent。
- 用户只输入自然语言，不填写内部 `eid`，也不选择 SQL、图查询或证据检索模式。
- Agent 必须调用 `investigate_company`，再由 `CompanyDueDiligenceAgent.investigate` 完成企业解析、工具计划、来源校验和报告任务。
- 企业尽调不提供独立页面或侧边栏入口，统一使用主聊天窗口。

## 修复内容

- 运行时工具解析同时接受 `buildin` 与 `company_due_diligence` 分类，确保已配置的 `investigate_company` 真正绑定到 Agent。
- Agent 配置选项保留企业尽调领域工具，避免运行上下文规范化时将其过滤。
- 启动阶段修复历史企业尽调 Agent 的后端类型、全局共享权限、系统提示词和工具配置，同时保留已有模型等其他上下文设置。
- 工具 JSON Schema 强制要求 `question`，兼容历史 `message` 输入但不再向模型暴露两个可选问题字段。
- 删除独立调查页面和重复侧边栏入口。

## 运行配置

企业尽调 Agent 需要绑定一个已启用、余额正常且支持工具调用的对话模型。2026 年 8 月 12 日真实 E2E 首次复现默认供应商返回 HTTP 402“余额不足”；当前部署已切换到通过连通性检查的 `deepseek:deepseek-v4-flash`，随后主聊天工具调用成功。

该模型选择属于部署数据库中的 Agent 配置，不写入广东企业源数据库，也不在仓库中保存任何密钥。

## 验收标准

- [x] 企业尽调只从主聊天窗口进入。
- [x] 侧边栏不再展示独立企业尽调工作台。
- [x] 主聊天可以发现并选择唯一全局企业尽调 Agent。
- [x] 历史 Agent 自动补齐 `investigate_company` 和全局权限。
- [x] 运行时实际绑定 `investigate_company`，而不只是数据库中存在工具名。
- [x] 工具调用必须提供非空 `question`。
- [x] 主聊天全局问题真实调用工具并将成功结果写入会话历史。
- [x] 模型供应商故障与企业尽调工具故障可以通过日志和 E2E 区分。
